# Localization (i18n) Guide

Zetawala keeps **English URLs unchanged** and adds language prefixes for other locales.

This is not a rewrite of the Next.js App Router. Existing English routes, sitemaps, canonicals, and the writing-tool language variants (`/tools/writing/ai-humanizer-spanish`, etc.) stay as they are. Those writing URLs describe the **language of the text being processed**, not the UI locale.

## Supported locales

| Code | URL prefix | HTML `lang` | Status |
| --- | --- | --- | --- |
| `en` | none (default) | `en` | Live English site |
| `es` | `/es` | `es` | Enabled |
| `fr` | `/fr` | `fr` | Enabled |
| `de` | `/de` | `de` | Enabled |

English examples:

```text
https://www.zetawala.com/
https://www.zetawala.com/calculators
https://www.zetawala.com/tools/calculators/profit-margin-calculator
https://www.zetawala.com/tools/youtube/youtube-niche-finder
```

Localized examples:

```text
https://www.zetawala.com/es
https://www.zetawala.com/es/calculadoras
https://www.zetawala.com/es/escritura
https://www.zetawala.com/es/tools/calculators/calculadora-de-margen-de-beneficio
https://www.zetawala.com/es/tools/youtube/youtube-niche-finder

https://www.zetawala.com/fr/calculateurs
https://www.zetawala.com/de/rechner
```

There is **no** `/en/...` public URL. `/en` 308-redirects to the unprefixed English path.

There is **no** automatic `Accept-Language` redirect. Crawlers can request every locale URL independently.

## Architecture

| Piece | Location |
| --- | --- |
| Locale registry | `src/i18n/config.js` |
| What is published | `src/i18n/catalog.js` |
| Public tool inventory | `src/i18n/registry.js` |
| Path / slug helpers | `src/i18n/paths.js` |
| Hreflang | `src/i18n/hreflang.js` |
| Language switcher targets | `src/i18n/switcher.js` |
| Dictionaries | `src/locales/{locale}/*.json` |
| Prefix routes | `src/app/[locale]/[[...slug]]/page.js` |
| Middleware | `src/middleware.js` |
| Draft → runtime packs | `scripts/i18n/build-locale-packs.mjs` |

English pages continue to live under `src/app/` (not moved into `[locale]`).

Prefix locales are resolved by a catch-all that **only** renders resources listed in `catalog.js`. Unknown combinations 404.

## How to add a new locale

1. Add the code to `SUPPORTED_LOCALES` and `ENABLED_LOCALES` in `src/i18n/config.js`.
2. Add `LOCALE_META` (html lang, OG locale, native name).
3. Create `src/locales/{code}/` by copying `en/` and translating.
4. Register the new JSON loaders in `src/i18n/dictionary.js`.
5. Translate only pages that have real copy. Do not enable the locale until translations exist.

## How to add translations

Runtime namespaces under `src/locales/{locale}/`:

- `common.json` — nav, footer, switcher, search, localized tool names
- `home.json` — localized homepage
- `calculators-hub.json` — localized calculators hub
- `hubs.json` — suite hubs (SEO, writing, study, freelancer, Shopee, Lazada, PDF)
- `legal.json`, `contact.json`, `blog.json`
- `tools/{internalSlug}.json` — hand-written packs for the six launch calculators
- `tool-copy.json` / `tool-names.json` — generated packs for every public tool

Compact drafts live in `scripts/i18n/en-split/` (English source) and `scripts/i18n/translations/{locale}/` (es/fr/de). Expand them with:

```bash
npm run i18n:build
npm run i18n:check
```

Draft shape per internal slug:

```json
{
  "name": "...",
  "desc": "...",
  "title": "...",
  "description": "...",
  "keywords": ["..."],
  "example": { "input": "...", "output": "..." },
  "faqs": [["question", "answer"]]
}
```

Load dictionaries with `getDictionary(locale, namespace)` on the server. Do not import every language into a client component.

## How to add localized slugs

Natural localized slugs are listed in `SLUG_OVERRIDES` in `src/i18n/catalog.js`. Every other public tool reuses its English `seoSlug` under `/es/tools/{folder}/{seoSlug}` (and the same for `fr` / `de`).

Do not auto-translate every slug. Only localize when the slug is natural for that language.

The English slug under a prefix locale is **not** an alias when an override exists. `/es/tools/calculators/profit-margin-calculator` 404s because Spanish uses `calculadora-de-margen-de-beneficio`. That avoids duplicate localized URLs.

## How to enable localization for a new tool

New public tools are picked up automatically from `listPublicTools()` once they are active in navigation. To ship translated copy:

1. Add the tool to the matching file in `scripts/i18n/en-split/`.
2. Translate `scripts/i18n/translations/{es,fr,de}/{category}.json`.
3. Run `npm run i18n:build` so `tool-copy.json`, `tool-names.json`, and `common.json` tools names stay in sync.

Until a draft exists, the builder falls back to English copy for that slug. Do not leave that fallback in production for a published prefix URL.

## Metadata, canonical, hreflang

- English tool metadata still comes from `src/config/toolMetadata.js` via `buildToolPageMetadata`.
- Localized metadata comes from each tool/page dictionary.
- Each localized URL has a **self-referencing canonical**.
- Translations are **not** canonicalized to English.
- `hreflang` (including `x-default` → English) is generated for every published locale of that resource.

## Sitemap

`src/app/sitemap.js` still emits English URLs, then appends `listLocalizedSitemapEntries()`. English entries for localized resources include `alternates.languages`. Prefix-locale URLs are added once; redirects, 404s, and unknown paths are omitted.

## Language switching

`LanguageSwitcher` lives in the header (desktop and mobile). It:

- reads the current locale from the URL (the root layout does not re-render on client navigations, so a server-passed locale would stick on English)
- uses a full page load so chrome locale stays aligned with the URL
- preserves the current tool/page when a translation exists
- falls back to that language’s homepage when the path is unknown
- never invents a broken URL

Navbar, footer, and search links use that same URL locale, so moving between tools after a language switch stays in that language.

## Robots

`src/app/robots.txt` already allows `/`. Localized prefixes are crawlable. No extra disallow rules were added.

## Published in `es` / `fr` / `de`

- Homepage
- Calculators hub and the other suite hubs (SEO, writing, study, freelancer / Upwork / Fiverr, Shopee, Lazada, PDF utilities)
- Contact, privacy, terms, cookies, blog listing
- Every active public tool

Natural localized slugs exist for: `profit-margin`, `break-even`, `freelance-hourly-rate`, `salary-to-hourly`, `customer-ltv`, `adsense-revenue`. Other tools keep the English `seoSlug`.
